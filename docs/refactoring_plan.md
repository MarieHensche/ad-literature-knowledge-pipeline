# Refactoring Plan

This plan builds on `docs/pipeline_summary.md`. The goal is to make the
pipeline easier to debug, maintain, and extend without losing the usefulness of
the current script-based workflow.

## Implementation Status

The refactor has been implemented through the main pipeline and collection
workflow layers:

- Phase 0 behavior tests and non-LLM smoke coverage were added.
- The `ad_lit_pipeline/` package skeleton, IO helpers, core step types, and
  artifact conventions were added.
- Main non-LLM steps, rule-based screening, LLM steps, provider dispatch, and
  orchestrators now live in package modules.
- `scripts/` now acts as a compatibility wrapper layer for migrated steps.
- Topic contract support, prompt templates, shared LLM tracing, OpenAlex
  provider isolation, manifests, dry-run, explain, only-step, from-step, and
  resume options are in place.

Remaining follow-up outside this pass: generate or validate the legacy YAML
schema from the topic contract so schema drift is impossible.

## Desired End State

The pipeline should have four clear layers:

1. Topic contracts define research meaning.
2. Step modules define pipeline behavior.
3. Providers define external data-source integrations.
4. Orchestrators define order, paths, manifests, and resumability.

The current `scripts/` directory can stay as a command-line interface layer, but
the real logic should move into an importable Python package.

## Core Design Rules

- `scripts/` should be thin wrappers. They parse CLI arguments and call package
  functions.
- `ad_lit_pipeline/steps/` should own behavior. Each pipeline task should be in
  exactly one obvious module.
- `ad_lit_pipeline/topics/` should own research meaning. Scope terms, include
  criteria, exclude criteria, fallback policies, topic descriptions, and tagging
  categories should not be hidden inside prompt strings or script constants.
- `ad_lit_pipeline/prompts/templates/` should own prompt text. Prompts should be
  rendered from templates plus the topic contract.
- `ad_lit_pipeline/providers/` should own external APIs. OpenAlex behavior
  should not be mixed into generic collection steps.
- Every step should declare its inputs, outputs, LLM usage, and important
  decisions.
- Every LLM call should be traceable by saving the rendered prompt, schema,
  model, response, and parsed output.

## Environment And Dependency Boundary

This refactor should not change the project's packaging model yet.

- Keep `requirements.txt` as the runtime dependency file.
- Keep `.venv` as the local virtual environment convention.
- Do not introduce `pyproject.toml`, package build metadata, lockfiles, or a new
  dependency-management workflow as part of this refactor.
- Add runtime dependencies only when they are necessary for a refactoring phase.
- If a dependency is added, document it in `requirements.txt`.
- Jupyter-only tools such as `ipykernel` and `ipywidgets` should not be added to
  runtime requirements.

## Autonomous Execution Model

This plan is meant to be worked down continuously by an agent, not treated as a
single tiny first PR.

The expected loop is:

1. Read the relevant docs and current scripts.
2. Pick the next phase or next step in the phase order.
3. Make the smallest coherent code change for that step.
4. Run focused tests or smoke checks.
5. Fix failures.
6. Continue to the next step.
7. Stop only when the plan is complete, a real blocker is reached, or the user
   asks to pause.

Do not stop merely because one step was migrated successfully. After each
successful migration, update or add tests, verify behavior, then continue to the
next step in the plan.

## Topic Contract

The biggest conceptual refactor is to create a single topic contract file. This
file can be written by the user or generated by an LLM and then edited by the
user.

Example target shape:

```yaml
topic_id: early_detection_ad

research_topic:
  title: Early detection of Alzheimer's disease and related impairment
  description: >
    Computational papers about early detection of Alzheimer's disease,
    mild cognitive impairment, dementia, or dementia-related cognitive
    impairment.

scope:
  include_criteria:
    - computational or data-driven early detection
    - AD, MCI, dementia, or dementia-related cognitive impairment
  exclude_criteria:
    - drug discovery
    - treatment response
    - care support without detection
  boundary_rules:
    - If a paper says early diagnosis but only performs AD-vs-control
      classification, keep it in scope but tag the comparison accurately.

rule_based_screening:
  include_terms:
    - early detection
    - early diagnosis
    - mild cognitive impairment
    - mci
    - screening
    - classification
    - diagnosis
    - detecting
    - detection
  exclude_terms:
    - drug repurposing
    - drug discovery
    - treatment
    - treatment response
    - care support
  exclude_wins: true

candidate_screening:
  missing_abstract_policy: exclude
  borderline_policy: exclude
  human_review_policy: exclude

tagging:
  fallback_policy:
    prefer_unclear_when_allowed: true
    prefer_mixed_or_unclear_when_unclear_missing: true
    missing_information_value: not_reported
    knowledge_confidence: very_low
    review_status: needs_decision
  categories:
    primary_clinical_target:
      values:
        - ad
        - mci
        - dementia
        - cognitive_impairment
        - prodromal_ad
        - preclinical_ad
        - mixed_or_unclear
        - unclear

collection:
  allowed_providers:
    - openalex
  preferred_provider: openalex
  max_results_default: 25
```

This replaces or generates from the current combination of:

- `configs/early_detection_tagging_config.yaml`
- `docs/early_detection_scope.md`
- hard-coded terms in `scripts/screen_scope.py`
- hard-coded candidate-screening rules in `scripts/screen_candidates_with_llm.py`
- hard-coded fallback rules in `scripts/generate_tagging_rules.py`
- hard-coded paper-tagging instructions in `scripts/tag_papers_with_llm.py`

## Step Contract

Each step should have a predictable shape.

```python
STEP = StepSpec(
    name="normalize_metadata",
    inputs=["raw_papers_csv"],
    outputs=["normalized_papers_csv"],
    uses_llm=False,
)

def run(context: RunContext) -> StepResult:
    ...
```

At minimum, each `StepResult` should include:

- step name
- input artifacts
- output artifacts
- row counts
- warnings
- error details, if failed
- elapsed time
- optional LLM trace paths

This makes it possible to add:

```bash
python scripts/run_pipeline.py explain ...
python scripts/run_pipeline.py run --only-step screen_scope ...
python scripts/run_pipeline.py run --from-step tag_papers ...
python scripts/run_pipeline.py run --dry-run ...
```

## Step Registry

Add one registry that lists available steps and pipeline order.

```python
MAIN_PIPELINE = [
    "normalize_metadata",
    "screen_scope",
    "normalize_tagging_config",
    "generate_tagging_rules",
    "tag_papers",
    "audit_extraction",
    "export_mantis",
]

COLLECTION_PIPELINE = [
    "plan_search",
    "fetch_candidates",
    "deduplicate_candidates",
    "screen_candidates",
    "export_included_candidates",
]
```

The registry should also know which module owns each step. This turns the
pipeline into a searchable map instead of requiring someone to read orchestration
code and every script.

## Run Manifest

Each run should write a manifest:

```text
runs/<run_id>/
  manifest.json
  artifacts/
  logs/
  prompts/
  responses/
```

The manifest should record:

- run id
- collection name
- topic contract path and hash
- model settings
- each step's input and output paths
- row counts before and after each step
- generated prompt paths
- response paths
- start and end timestamps
- failed step, if any

This is the most important debugging improvement after the topic contract.

## Prompt And LLM Trace Refactor

Move prompts out of Python strings into templates:

```text
ad_lit_pipeline/prompts/templates/
  plan_search.md
  screen_candidate.md
  generate_tagging_rules.md
  tag_paper.md
```

The renderer should combine:

- prompt template
- topic contract
- paper or candidate data
- allowed values
- generated fixed rules, when needed

For every LLM call, save:

- rendered prompt
- system message
- response schema
- model
- raw response
- parsed JSON
- validation result

This makes "why did the model choose that?" answerable.

## Specific Problems This Refactor Fixes

### Hidden Topic Logic

Current problem:

- Include/exclude terms live in `scripts/screen_scope.py`.
- Candidate-screening policy lives inside `scripts/screen_candidates_with_llm.py`.
- Fallback rules live inside `scripts/generate_tagging_rules.py`.
- The scope document and tagging config are separate and can drift.

Refactor:

- Move all topic-specific logic into the topic contract.
- Render prompts from the contract.
- Validate that prompts and rule-based screening are using the same contract.

### Metadata Loss

Current problem:

- `scripts/screen_scope.py` drops optional metadata columns such as authors,
  venue, source, URL, and full text path before paper tagging.

Refactor:

- Preserve all input columns and append screening fields.
- Add explicit output-column tests for every step.

### Unsupported Provider Branches

Current problem:

- `plan_library_search.py` lets the LLM choose Semantic Scholar, Europe PMC,
  Crossref, or OpenAlex.
- `fetch_openalex_candidates.py` only supports OpenAlex.

Refactor:

- Topic contract lists `allowed_providers`.
- The planner receives only allowed providers.
- Provider implementations live behind a common interface.
- Unsupported providers are impossible to choose unless explicitly enabled.

### Schema Drift

Current problem:

- `schemas/early_detection_knowledge_schema.yaml` and
  `configs/early_detection_tagging_config.yaml` disagree on some values, such as
  `review_status`.

Refactor:

- Topic contract becomes the source of truth.
- Generate or validate tagging config, schema, and Mantis export mapping from
  the same category definitions.

## Step-By-Step Migration Plan

### Phase 0: Lock Current Behavior

Goal: make refactoring safe.

1. Add a small test fixture using `data/raw/example_papers.csv`.
2. Add smoke tests for the non-LLM steps:
   - normalize metadata
   - rule-based scope screening
   - audit extraction with a tiny fixture
   - export Mantis CSV with a tiny fixture
3. Add golden-file tests for importers:
   - BibTeX to canonical CSV
   - JSON/JSONL to canonical CSV
   - RIS to canonical CSV
4. Document current known quirks:
   - metadata loss after scope screening
   - non-OpenAlex provider plans fail at fetch time
   - empty included set fails later during Mantis export
   - schema/config `review_status` mismatch

Deliverable:

- A minimal test suite that protects current behavior before moving files.

### Phase 1: Create The Package Skeleton

Goal: create homes before moving behavior.

1. Add `ad_lit_pipeline/__init__.py`.
2. Add `ad_lit_pipeline/io/` helpers for CSV, JSON, JSONL, and YAML.
3. Add `ad_lit_pipeline/core/artifacts.py` for common artifact names.
4. Add `ad_lit_pipeline/core/context.py` for collection name, paths, run id,
   model settings, and topic contract path.
5. Add `ad_lit_pipeline/core/step.py` with `StepSpec` and `StepResult`.
6. Keep all current scripts working.

Deliverable:

- A package skeleton with no behavior changes.

### Phase 2: Move Simple Non-LLM Steps First

Goal: prove the module pattern with low-risk steps.

Move logic in this order:

1. `normalize_metadata.py` to `steps/metadata/normalize.py`.
2. `deduplicate_candidates.py` to `steps/collection/deduplicate.py`.
3. `export_screened_candidates_to_csv.py` to `steps/collection/export_included.py`.
4. `audit_extraction.py` to `steps/tagging/audit.py`.
5. `export_mantis_ready.py` to `steps/export/mantis.py`.

For each move:

- Copy logic into the package module.
- Update the original script to call the package module.
- Keep CLI arguments compatible.
- Run the related smoke test.

Deliverable:

- Several scripts are thin wrappers, and behavior remains unchanged.

### Phase 3: Add Topic Contract Support

Goal: establish the central source of truth.

1. Add `ad_lit_pipeline/topics/contract.py`.
2. Add a topic-contract schema or validator.
3. Add `configs/topics/early_detection_ad.yaml` as the first topic contract.
4. Populate it from:
   - `configs/early_detection_tagging_config.yaml`
   - `docs/early_detection_scope.md`
   - include/exclude terms from `scripts/screen_scope.py`
   - prompt policies from LLM scripts
5. Add a converter that can produce the current normalized tagging config shape
   from the topic contract.
6. Keep `--tagging-config` working temporarily, but add `--topic-contract`.

Deliverable:

- The pipeline can run from a topic contract while legacy config still works.

### Phase 4: Refactor Rule-Based Screening

Goal: remove hard-coded include/exclude terms and preserve metadata.

1. Move `screen_scope.py` logic to `steps/screening/rule_based_scope.py`.
2. Read `include_terms`, `exclude_terms`, and `exclude_wins` from the topic
   contract.
3. Preserve all input columns.
4. Append:
   - `scope_decision`
   - `scope_reason`
   - `scope_matched_include_terms`
   - `scope_matched_exclude_terms`
5. Add tests for:
   - include match
   - exclude match
   - exclude wins
   - no match means `needs_decision`
   - optional metadata is preserved

Deliverable:

- Scope screening is topic-driven and no longer erases useful metadata.

### Phase 5: Move Prompt Text To Templates

Goal: make prompts inspectable and editable.

1. Add prompt templates:
   - `plan_search.md`
   - `screen_candidate.md`
   - `generate_tagging_rules.md`
   - `tag_paper.md`
2. Add `prompts/render.py`.
3. Render templates using the topic contract and per-step data.
4. Remove hard-coded topic rules from Python prompt strings.
5. Save rendered prompt files during runs.

Deliverable:

- Prompt behavior is visible outside Python code.

### Phase 6: Add LLM Client And Tracing

Goal: centralize OpenAI usage and make decisions debuggable.

1. Add `ad_lit_pipeline/llm/client.py`.
2. Add `ad_lit_pipeline/llm/schemas.py` for response schemas.
3. Add `ad_lit_pipeline/llm/trace.py`.
4. Route all OpenAI calls through the shared client.
5. Save for each call:
   - system message
   - rendered prompt
   - model
   - response schema
   - raw response
   - parsed response
6. Add a fake LLM client for tests.

Deliverable:

- LLM behavior is centralized, traceable, and testable without API calls.

### Phase 7: Refactor LLM Steps

Goal: make LLM tasks modular and contract-driven.

Move and refactor:

1. `plan_library_search.py` to `steps/collection/plan_search.py`.
2. `screen_candidates_with_llm.py` to
   `steps/screening/llm_candidate_screening.py`.
3. `generate_tagging_rules.py` to `steps/tagging/generate_rules.py`.
4. `tag_papers_with_llm.py` to `steps/tagging/tag_papers.py`.

For each step:

- Use prompt templates.
- Use topic contract policy.
- Use shared LLM client.
- Save traces.
- Keep old CLI wrappers working.

Deliverable:

- LLM steps are modular, prompt-driven, and traceable.

### Phase 8: Refactor Providers

Goal: remove OpenAlex-specific code from generic collection flow.

1. Add `providers/base.py` with a common provider interface.
2. Move OpenAlex URL building, fetching, and record conversion into
   `providers/openalex.py`.
3. Make `steps/collection/fetch_candidates.py` dispatch to the selected
   provider.
4. Pass only enabled providers from the topic contract to the planner.
5. Add placeholder modules for Semantic Scholar, Europe PMC, and Crossref only
   if the interface is clear. Otherwise, leave them out until implemented.

Deliverable:

- The collection flow can grow beyond OpenAlex without changing core pipeline
  orchestration.

### Phase 9: Add Run Manifest And Step Runner

Goal: make pipeline runs inspectable and resumable.

1. Add `core/manifest.py`.
2. Add a step runner that:
   - resolves artifacts
   - records inputs and outputs
   - records row counts
   - records elapsed time
   - records warnings and errors
3. Write run output under `runs/<run_id>/`.
4. Add CLI options:
   - `--run-id`
   - `--dry-run`
   - `--only-step`
   - `--from-step`
   - `--resume`
   - `--explain`

Deliverable:

- A failed run can be inspected and resumed without re-reading every script.

### Phase 10: Thin CLI Wrappers And Cleanup

Goal: make the repository easy to navigate.

1. Update `scripts/run_pipeline.py` and `scripts/run_collection.py` to delegate
   to `ad_lit_pipeline/cli/`.
2. Keep old single-step script names temporarily for compatibility.
3. Mark old script wrappers as deprecated once the new CLI works.
4. Update README commands.
5. Update `docs/pipeline_summary.md` after the refactor lands.
6. Add a `docs/module_map.md` if the package grows further.

Deliverable:

- `scripts/` remains familiar, but the package structure is the real map.

## Autonomous Refactoring Sequence

Work through the phases in order. Within each phase, migrate one coherent unit,
test it, fix failures, and then continue.

Recommended first units:

1. Add the package skeleton.
2. Add tests around current behavior where practical.
3. Move `normalize_metadata.py` into `ad_lit_pipeline/steps/metadata/normalize.py`.
4. Turn `scripts/normalize_metadata.py` into a compatibility wrapper.
5. Test the wrapper and package module.
6. Continue with the next simple non-LLM step from Phase 2.

Continue this loop through the rest of the plan:

- simple non-LLM steps
- topic contract support
- rule-based screening
- prompt templates
- shared LLM client and tracing
- LLM step refactors
- provider refactors
- run manifest and step runner
- final CLI cleanup and documentation updates

## Acceptance Checklist

The refactor is successful when:

- A new contributor can find each pipeline task by looking under
  `ad_lit_pipeline/steps/`.
- Topic behavior is visible in one topic contract file.
- Prompt behavior is visible in prompt templates.
- Every LLM decision has a saved prompt and response.
- The OpenAlex provider can be modified without touching tagging code.
- The main pipeline can run step-by-step, resume, and explain itself.
- Existing CLI commands still work or have documented replacements.
- Metadata needed by later steps is not silently dropped.
- Schema, tagging config, and Mantis export mapping cannot drift silently.
